# 0004 加班一次最多四段（2026-11-21）

接 0002「一次填兩段」。門市加班常被切成三、四段（午休前後、收班後），原本一張單最多兩段，要拆成兩張單送。Eason 要改成最多四段。

## 規格（大腦依現況定的預設）
- **只有加班開到四段**；請假、出差維持最多兩段，忘打卡不分段。上限依類別設（`Requests.gs` `REQ_SEG_MAX_N_`：ot 4、leave 2、trip 2），不是把 2 改成 4。
- 店長代開加班同步四段（營運系統「幫同仁開單」，mala-store-ops 同名分支）；代開請假、出差仍不分段。
- 加班合計上限維持 10 小時（`REQ_OT_MAX_H`、營運系統 `SEG_MAX_OT_ADMIN`），單段也是 10。
- 各段兩兩比對：任兩段重疊、接在一起都擋。兩段的訊息跟以前一字不差；三、四段講「第 X 段和第 Y 段」。
- 資料格式不變：每段一列、同一次送出同一個 `grp`、`__seg` 1…4（依時間先後）；沒動試算表欄位、`Payroll.gs`、核定規則（規則甲乙）。
- 第五段／請假出差第三段：`bad_segments`，「加班一次最多填四段時間」「請假、出差一次最多填兩段時間」。

## 相容
- `req_info.ot_segments_max`：開關有開回 4、沒開回 1。申請頁依這個決定加班能「＋ 加一段」到第幾段；**舊後端回 2（或沒這欄）時新申請頁只加到第二段，畫面跟 2026-11-18 一樣**。順序不限：先換申請頁或先換後端都不會壞（先換後端、申請頁沒換＝舊申請頁還是只到兩段）。
- 開關 `REQ_SEG2_KINDS` 讀法不變（`ot,leave,trip`，沒設＝全關，送多段一律 `seg2_off`）。只要 `ot` 在裡面，加班就是四段；沒有另一個「只開兩段」的開關。要退回四段 → 退回後端檔（舊檔 `ot_segments_max` 回 2）；要整個關 → 屬性改空字串。

## 核定側確認（沒改程式，測試鎖住）
`reqBindCheck_`（加班時數、時段在不在核定內 `ot_slot`、班表內 `ot_in_sched`、打卡佐證 `ot_punch`）本來就逐張已核准加班單算；`tests/seg4.test.js` G1–G3 用「四段一次送」對「分四次送」逐欄比，結果相同。
